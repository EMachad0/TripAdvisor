# Decisions (curator platform build, 2026-11-09)

Made AFK by the orchestrator while building the curator platform. Change them if the traveler disagrees.

## Layout
| Path | Owner | What |
|---|---|---|
| `platform/` | coder | Node 24 ESM code: schema, renderer, CLI, media, runner, feedback reader, tests |
| `platform/test/fixtures/` | coder | The only place-like content the coder may write. Every fixture is marked `fixture: true` and is never built into the real site |
| `places/` | curator | Real content. `places/<country>/<city>/<slug>/place.yaml` + `media/` |
| `areas/` | curator | Area/city cards for the broad round. `areas/<country>/<slug>.yaml` |
| `feedback/` | game app | JSONL logs the game appends to (`swipes.jsonl`, `duels.jsonl`, `questions.jsonl`). Curator reads only |
| `config/trip.yaml` | orchestrator | Trip facts the gap report needs (countries, days, budgets, dates) |
| `build/` | generated | Static site + screenshots. Git-ignored |
| `runs/` | generated | Headless runner logs. Git-ignored |

## Format
- **YAML, one file per place** (`place.yaml`), with a `blocks:` list for the page. Agents write YAML reliably, it diffs well, and a schema can point at an exact path (`blocks[3].items[1].price_local`). Long text fields accept a small Markdown subset (bold, italics, links, lists).
- Schema in code with **fix-it messages**: each error states the path, what is wrong, what is expected, and an example value.
- Same schema is exported as JSON Schema so the game can reuse it.

## Money
- Every price has local amount + currency + R$ amount. Each place records `fx: {rate, date, source}` (1 local = X BRL). The CLI has an `fx` command (free ECB-based API) so the curator never guesses a rate. Validator warns when R$ ≠ local × rate (±5%).

## Media
- Wikimedia Commons first (API search + exact file). Author, license, license URL and source URL captured automatically into `media/credits.yaml`. Images resized to WebP at several widths for `srcset`.
- Non-free images are rejected by the Commons fetcher. **Superseded 2026-11-25:** photos no longer need a free licence (see "Photos from the web" at the end).

## Rendering
- Pure function `renderPlacePage(place) → HTML` in `platform/lib/`, so the game can reuse it. Fonts bundled locally (no CDN needed at view time). Light/dark via `prefers-color-scheme` plus a toggle.
- Maps: coordinates + deep links per country (China → Amap/Baidu, Korea → Naver/Kakao, else Google/Apple) and an OpenStreetMap embed.

## Screenshots
- Playwright-core driving the installed Google Chrome (`channel: "chrome"`), desktop 1440 wide and phone 390 wide, light and dark.

## Headless curator
- `atr run "<task>"` runs `claude -p` with the curator guide appended to the system prompt, then loops validate → feed errors back → re-run, up to N rounds, logging to `runs/`.

## Feedback
- JSONL, one event per line, append-only, versioned (`v: 1`). Spec in `docs/FEEDBACK-FORMAT.md`.

## Coder notes (platform build, 2026-11-09)
Small refinements and deviations, each with the reason:
- **Custom schema DSL instead of zod/ajv** (`platform/lib/schema/dsl.js`). One spec drives validation, fix-it messages (path, problem, expected, example, "did you mean"), YAML line numbers, `./atr blocks` docs and the JSON Schema export.
- **`book_ahead.lead_days`** (integer) is required when `required: true`, so the game can sort the book-ahead list by deadline. A free-text `lead_time` is optional.
- **Area media** live in `areas/<country>/media/` (shared per country), with the same `credits.yaml` format as places.
- **Fixture mode**: `--fixtures` or `ATR_FIXTURES=1` swaps `places/ areas/ feedback/` for `platform/test/fixtures/`. Fixture builds go to `build/fixtures/` so they never mix with the real site, and real loads skip any `fixture: true` file. `ATR_DATA_ROOT=<dir>` points at any other data root (used by tests).
- **Screenshots**: full-page shots render at 1× device scale (Chrome can't capture more than 16384 device px tall); `--viewport` shots of phone pages use 2×. Phone width is 390.
- **CJK/Thai text** uses system fonts (PingFang, Hiragino, Apple SD Gothic, Noto). Only Fraunces and Inter (Latin) are bundled, to keep the assets small.
- **The runner** uses `--permission-mode dontAsk`, an allow-list of tools, and `--disallowedTools` for edits to `platform/ docs/ config/ feedback/`. It also snapshots files outside `places/` and `areas/` and reports changes. `claude` has no `--max-turns` flag here; use `--max-budget-usd` and `--timeout-min` instead.
- **Placeholders**: any `TODO` left from the scaffold is a validation error.

## Coder notes, round 2 (curator friction + design review, 2026-11-09)
- **Static map instead of the live embed.** At build time `lib/staticmap.js` stitches OSM tiles (identifying User-Agent, cached in `.cache/tiles`, only a few dozen tiles per place) into `build/places/<id>/map.webp`. The pin and the "© OpenStreetMap contributors" credit are HTML overlays, so the pin keeps its colour in dark mode (the map image is inverted/desaturated there). The `map.embed: false` field still hides the map. The iframe is gone. If tiles can't be fetched, a "Open map" placeholder links to openstreetmap.org.
- **Typographic hero.** `hero.image` is now optional. Without it the hero uses the category gradient, a dot texture and the local-script name as a watermark. Swipe cards do the same. New `hero.caption` lets the curator be honest about a nearby/area photo.
- **Balanced grids.** `lib/render/layout.js` lays out galleries (1–8) and quick facts (any count) without orphan tiles. With an odd count the first gallery photo is the wide "feature" (`feature: false` disables it), and rows of portrait photos get 4:5 tiles. The validator uses the same maths to warn about too-small or badly cropped photos (hero < 1600 px or portrait; feature < 1280 px; 2-per-row < 900 px).
- **Food budget.** New optional `counts_against_budget`. It defaults to false for category `food` / kind `Eat`. Those pages say "Meal cost" and compare with `cheap_meal_brl`, a rough per-country reference I added to `config/trip.yaml` (orchestrator, please correct the values if you have better ones). `gaps` skips them in the budget-outlier check, and the game should use `countsAgainstBudget()`.
- **Booking.** New `book_ahead.links: [{label, url, note}]` (the old `link` still works) and `book_ahead.rules_changed: {date, note}`, shown as a badge on the hero, the quick facts and the booking panel. The panel no longer prints the generic method description, and `passport_note` + `notes` are merged into one callout. Validate warns when `link` is a bare homepage.
- **Smaller additions.** `short_name` for headings (falls back to the part of `name` before a colon); quick-fact `extra[].detail` with automatic font shrinking for long values; warnings for duplicated automatic labels and long values; lede accent colour only when it starts with a letter; zero amounts render as "Free" / "–" consistently; the optional chip sits inline.
- **Media.** `atr media preview` downloads previews and a labelled contact sheet into `.cache/previews/<query>/`. Commons calls retry with exponential backoff (respecting Retry-After), are spaced ≥ 1.2 s apart across invocations, and fail with plain-language messages. The `atr new` hint strips punctuation and doesn't repeat the city. Scaffold comments now show `≤N chars` for every limited field.
- **Screenshots.** Extra `<id>-phone-<theme>-top.png` at 2×.
- Every change is backward compatible: the 3 curator places validate unchanged (they now get only warnings).

## Coder notes, round 3 (curator batch-2 friction + review, 2026-11-09)
- **Booking level.** `book_ahead.required` now also accepts `"recommended"`; `true` and `false` are unchanged. Recommended places need `lead_days` and `method`, show a softer outlined badge ("Booking recommended · 1 day ahead"), and appear in `bookAheadList()` after the required ones.
- **Booking logic in one module.** `lib/booking.js` is now the only code that reads `link`/`links` and `required`. Gaps, validate, the renderer and the card all go through it. The gaps false positive is fixed.
- **Media.** New `atr media remove <place> <name>` and `atr media prune <place> [--yes]`. Validate warns about media the page doesn't use and about the hero photo being repeated in the gallery. `focus:` on a portrait gallery photo now accepts the crop and silences the warning.
- **QR.** New `atr qr <image|url>` (dependency `jsqr`; `qrcode` is a dev dependency for tests only). It scans the full image plus 2×2 and 3×3 tiles, so a notice with WeChat and Trip.com codes returns both.
- **Screenshots.** Fixture shots now go to `build/fixtures/shots/`, fixing the collision between the real and fixture `yu-garden`. Automatic `-sNN` slices, plus `--section <block>` element shots at 2×.
- **Hero caption.** Now a small blurred pill with a camera icon: bottom-right on desktop, below the top bar on phone (no longer squeezed against the badges and quick facts).
- **Index.** Each country heading shows places · days · R$/day · dates, from `config/trip.yaml`.
- **Guide.** A Trip.com/Klook attraction or ticket page counts as a booking link even if it can't be fetched; record how you found it in `confidence_note`.

## Coder notes, round 4 (curator batch-3 friction, 2026-11-10)
- `atr qr` now always ends with a plain note: if the image shows more codes than were listed, the rest are probably WeChat "sun codes" (not QR, can't be decoded); use the official site or Trip.com/Klook. I tried a heuristic "N code-like regions" detector but dropped it: on real page images it reported photo textures as codes and missed sun codes. A wrong count is worse than an honest note.
- `atr shot` prints which blocks each `-sNN` slice shows. `--only phone|desktop` is an alias of `--device`. The guide now leads with `--section <block>` for re-checks after small edits.
- `confidence_note` max is now 400 (schema, JSON Schema export, scaffold, guide).
- The unused-media warning now reads "unused photo(s) in media/: … fetched but not shown on the page".
- New `info` level: validate hints when the page text says booking is required or recommended but `book_ahead.required` disagrees. Hidden by `--quiet`, not counted.

## Coder notes, round 5 (taste-aware and self-directing, 2026-11-10)
- **Stated taste.** `config/taste.yaml` has a spec in the schema DSL (`lib/taste.js`) and a loader. A missing file means no stated taste and the old flat rules; a malformed one is reported by `./atr taste` and `./atr validate --all` (exit 1). Fixture mode reads `platform/test/fixtures/config/taste.yaml`, so tests don't depend on the traveler's real answers.
- **`must_do` and `fame`.** Both optional in the schema, so existing places stay valid. The scaffold writes `fame: TODO` for attractions (a TODO is a validation error, so new places must choose); `gaps` flags places without it as low. Stays don't need `fame`.
- **Stay.** New category `stay`, tied to kind `Stay` both ways. `quick_facts.time_needed` and `best_time` became optional in the block schema so stays can skip them; the validator still requires them on every other place, so nothing changed for existing content. The stay colour is a muted brown (`#7d4f2c` / `#e3b792`): the blues, teals and purples were taken, and it sits apart from the saturated food orange.
- **Stats.** `gapReport().stats[country].places` now means attractions. Stays are in `stays`. The index page heading still counts every card.
- **Balance rules.** A category is "far under" when its expected count (target share × attractions) is at least 0.75 and it has less than half of that. It is "far over" when it has 3 or more places and more than twice its target share. Both start at 6 attractions. Numbers are in `GAP_DEFAULTS`, overridable in `trip.yaml`.
- **Discovery.** The hidden share is counted over all attractions, with places that have no `fame` counted as not hidden; the message says how many are unset.
- **`atr next` order.** Two deviations from the brief's order. Pages with validation errors come first, because every runner session validates everything and one broken page makes each later run "not clean". And an areas task follows every second must-do task instead of waiting behind all 16, so China's area cards are at rank 3.
- **New feedback.** There is no "processed" marker, so feedback counts as new when an event is dated after the newest `last_updated` of any place or area.
- **Runner attribution.** Bash matching is by path text: the full path, the absolute path, or `cd <dir>` plus the rest. Root files such as `atr` only count when the command writes to them, since `./atr …` appears in every session. A session that only reads a protected file with `cat` while another process changes it would be reported as a violation; that seemed the safer side to err on.
- **Allow-list.** `Agent` and `ToolSearch` added; `game/` and `package-lock.json` added to the deny rules.
- **Card top row** now wraps, so a long booking badge no longer runs off the card.
- **`./atr fx --amount`** prints the converted amount on the first line.

## Coder notes, round 6 (quality gates and dated events, 2026-11-10)
- **`when`.** Optional on places and areas. The overlap check uses the country's `from`/`to` in `trip.yaml`, both days included. No overlap is a warning, partial overlap an info line, and a place that looks date-bound without `when` gets an info hint only, since names like "festival" also appear on permanent places.
- **Link statuses.** Network errors that are not clearly DNS, refused or TLS failures count as `timeout` (a warning), because several Chinese hosts time out from here while the pages exist. Bot-walled hosts are classified without a request.
- **Duplicates.** A dated event never matches a permanent place at the same spot, only another event with overlapping dates. Otherwise every "X" and "X on New Year's Eve" pair would warn.
- **Reviewer permissions.** `Bash` is allowed in full so the reviewer can pipe and inspect output; the deny rules cover the edit tools and the `atr` commands that write content or start sessions. The runner also compares the file hash before and after and says so if `place.yaml` changed during the review.
- **Reviewer answer.** `claude -p --json-schema` exists, so the answer is taken from `structured_output`. The text fallback and the single retry stay for sessions where it is missing.
- **Verdict.** Computed by the runner from the issues (any blocker or should means `fix`); a verdict in the reviewer's answer is ignored.
- **Stale reviews.** When `place.yaml` changes, the old findings stop showing as open and the place is listed as "changed since its review". The alternative, showing possibly fixed findings as open, would send curators after problems that no longer exist.
- **Gates in the runner.** The review feedback round is on top of `--max-rounds`. A review that still says `fix` after it ends the run as not clean, and the findings stay in `reviews/` for `./atr next`. Gates only cover pages the session itself touched.
- **must_do `type`.** An explicit type restricts what covers the item. Without one, any claim still covers it, so nothing changes until the orchestrator sets the values.
- **Fixtures.** New `bund-nye-countdown` (dated, unconfirmed) and `reviews/yu-garden.yaml` (passing). The review's `content_hash` must match the yu-garden fixture file; a test says so when it drifts.

## Coder notes, round 7 (area pages and the feedback loop, 2026-11-10)
- **Area blocks.** Areas get their own tagged spec with nine block types. The hero block is optional and so is its `hook`; the page always has a hero built from `image`, `name`, `name_local` and `region`. `faq` is allowed on areas too.
- **Facts strip.** Suggested stay, cost level, getting there, getting around, with "best for" chips and the highlights in the bar below. The must-do, fame and date chips are in the hero, next to the name, as on place pages.
- **Overview map.** Pins are numbered north to south and the cards are reordered to match. The pin colour is fixed (not the category colour) so numbers read the same on every card. The zoom is capped at 9 so two neighbouring cities do not produce a street map.
- **Area page map.** Zoom 10 for a city and 7 for a region, rendered like place maps.
- **Area card.** `href` makes the name a link stretched over the whole card (the card stays an `article`, because the winter note may contain links). Cards also got `id="area-<id>"` so the map pins can jump to them.
- **Shots.** A place id wins over an area id; `--area` is the escape hatch. Area shots are prefixed `area-` so they cannot overwrite a place's shots.
- **Feedback cursor.** `--mark-seen` defaults to the newest event; `--new` prints the command with `--upto <ts>` so events that arrive while the curator works stay new. The cursor replaces the round-5 heuristic in `next`.
- **Signals.** Two or more new musts (or skips) in one category become one line, with the tag they all share if there is one.
- **Cost check.** The local-currency total must equal `cost.local`. The R$ check only fires when the two totals would be displayed differently (amounts from R$ 20 are shown without decimals), and it tells the curator to change the last item's `brl`, because `cost.brl = cost.local × fx.rate` is the number to keep. Totals are computed as before. Stays are skipped (their `cost` is the cheapest bed). The yu-garden fixture and the guide's worked example now mark the metro fare `optional`, since they showed exactly this mismatch.
- **Fixtures.** Harbin has a full page; `xian`, `shanghai` and `dali` are card-only areas with coordinates, so the overview map has four pins. They all reuse the one fixture photo.

## Coder notes, round 8 (fixes from real runs, 2026-11-10)
- **Why the second auto task failed.** The runner validated every file and sent all errors back, so the session spent two rounds on another curator's scaffolds and its own page was never re-reviewed. Now only the session's own files are judged; the rest is listed in `other_errors`.
- **Why `beijing` was attributed to that session.** Two causes. The id matched in a read (`head -5 areas/china/beijing.yaml`); and in round 3 the session really did edit `beijing.yaml`, because the runner had told it to fix that file. Attribution now needs a write, and the runner no longer sends other files' errors.
- **Inline scripts count as writes** when they name the path (or reach it through a shell variable set earlier in the command). A read piped into `python -c` does not.
- **Cost.** The stream confirms `total_cost_usd` is cumulative across `--resume` (1.632, 2.523, 3.013 for one session; `model_usage_since_last_result` sums to 1.632, 0.892, 0.489). The real cost of that run was $3.01 for the curator, not $7.17.
- **Spare round.** Review feedback now grants two extra curator rounds instead of one, so a fix that breaks validation can be repaired and still be re-reviewed.
- **Area reviews share `reviews/<id>.yaml`.** A place and an area with the same id would overwrite each other's review; `type` keeps the status honest (a review of the other type counts as "none"). Ids have not collided so far.
- **`media prune --area`** used to treat every photo not used as a card `image` as unused, which would have deleted photos used in area page blocks. It now only removes photos recorded for that area and unused by it; untagged photos are listed, never removed.
- **Hero scrim.** Attached to the text block instead of the hero, so it scales with the text. On a phone, where the text fills most of the hero, the photo is clear only in the top third; that is the price of a readable title on busy photos.
- **`./atr geo` User-Agent.** Nominatim asks for an identifying User-Agent; this one names a generic tool and nothing about the project or its user.
- **`./atr render`** refuses local and private addresses, keeps no cookies, and caps screenshots at 6000 px tall.
- **Link timeouts** stay warnings; the retry uses twice the first timeout (30 s by default).

## Coder notes, round 9 (2026-11-10)
- **Off-route wording.** "Not on your route" appears as a chip on the hero and the card and as a line in the When quick fact. Partial overlap gets no chip, only the usable days in the quick fact, because the visit is possible.
- **`kind: best` off the route** is an info line and reads "Best dates not on your route": the place can still be visited.
- **`season` label** is "From 20 Dec to 28 Feb", or "From about …" when `confirmed: false`.
- **City-level questions** are detected by wording ("how do I get to", "train from … to") plus the name of the place's own city, and never when the question names the place itself.
- **Area-missing** counts stays as places, and a region card whose `cities` list includes the city covers it.
- **Hero scrim.** The gradient now ends at 88% of the text box and has ten stops. The top 35–40% of a phone hero stays at full brightness even with a three-line title; the title carries a stronger shadow because its first line sits where the scrim is light.

## Coder notes, round 10 (2026-11-10)
- **`summary.content` changed meaning**: it is the attributed content, so every headline built from it is right by construction. The raw diff minus that is `also_changed_in_repo`.
- **Re-review.** The reviewer must give a status for each earlier finding; the runner, not the reviewer, decides what stays open: anything called open or not mentioned. If the answer has no `earlier` list at all (an old-style answer), the findings it did not repeat count as resolved.
- **On unchanged text a re-review raises only blockers.** That is what stops the loop from restarting; a fair new "should" on old text waits for the next full review (`--full`).
- **Copies of reviewed files** live under `.cache/reviewed/`, not in `reviews/`, so the review folder stays one file per page. Reviews written before this round have no copy, so their next review is a full one.

## Coder notes, notes on cards (2026-11-10)
- **`allowEmpty` in the schema DSL.** `text: ""` must be valid (it clears a note), but required strings reject empty values. A new `allowEmpty` flag keeps `text` required and allows `""`.
- **The server skips unchanged saves.** Autosave fires on blur and after a pause, so the same text can arrive twice. `/api/note` compares with the latest line and answers `unchanged: true` without appending, so the log only grows when the note really changes.
- **Text is trimmed** (and CRLF normalised) before it is stored, so "only whitespace" counts as clearing.
- **My calls lists notes on unswiped cards too** (verdict shown as none), so a note written in the deck before swiping never disappears from view.
- **Notes use their own colour token (`--note`, blue ink).** `--accent` changes per category and the verdict colours mean must/maybe/skip, so neither could mark "your words" consistently.
- **The Ask prompt** wraps the note in `<traveler_note>` tags with a label saying the traveler wrote it, and adds their current call.

## Coder notes, round 11B (renderer, schema, runner, 2026-11-12)
- **Cost block budget line.** The text shows the real share ("Over budget: 112% of your R$ 100/day Thailand budget (R$ 12 more)"); only the bar's fill stops at 100%, striped in the warn colour. Pages that added a note saying "the bar stops at 100%" (erawan-falls and the Thailand fix pass) can drop it; that is the curators' call.
- **One number format per cost column.** If any row needs centavos, every row gets them (R$ 49,00 next to R$ 2,48). The total keeps the quick-fact format, so the hero and the total still match.
- **Runner and the usage limit.** A round whose result is `is_error` (or `api_error: usage_limit_reached`) is a failed round: no resume, gates skipped, `clean: false`, and `why_not_clean` says "usage limit reached … resets <time>: the task is NOT done". `summary.usage_limit` carries the reset time and `--auto` stops starting new tasks. Before, the round counted as clean when the session had written nothing, or was resumed at "$0.000, 1 turns".
- **Runner timeout.** A round killed by `--timeout-min` is recorded in `cut_off_rounds`. If its files validate, the session gets one more round with a "you were cut off, finish the task" prompt (clean files after a cut-off do not mean the task is done, and the gates never ran). If the last round was cut off, `why_not_clean` says so.
- **Builds no longer collide.** `atr shot` (and so the reviewer) builds into `build/.private/<pid>-<time>/`, removed when the process exits; leftovers of dead processes older than 10 min are cleaned up. Shots still go to `build/shots/`. `atr build` / `atr preview` build into a staging folder and swap the five site entries in under `build/.build.lock`. Media and maps are hard-linked, so a private build costs no disk and takes about 3 s. `--no-build` still shoots the shared `build/`. `atr shot` therefore no longer refreshes `build/`: run `./atr build` for that.
- **Unfinished pages are not listed.** The renderer leaves places/areas holding `TODO` out of area pages, the index and the areas page (`hasPlaceholders`, exported for the game). The build also leaves out anything with a validation error (and from pairs_well and "On your list here"), but still builds its own page so curators can shoot it. `atr build` prints the unlisted ids.
- **credits.yaml errors are scoped.** Area media is shared per country. An area now gets only the errors of entries it uses (image, hero, gallery) or that were fetched for it (`area:`). An entry no area uses or owns is reported on the first area file of the country, once. The path names the photo (`[3].author ("three-chedi")`). 11A cleans the author at fetch time.
- **Schema additions (all optional, no existing file changes meaning):** `short_name` on areas (used in "Where … is"); `book_ahead.deadline` (badge "Book by 30 Nov", quick fact "By 30 Nov"; `lead_days` not required then; warning once it has passed); `method: platform` (labelled "Book on Hostelworld" from the first link's host); `tel:` URLs in `book_ahead.links[].url`, a call button, with a warning unless `method: phone`; `when.dates[].to` may be left out for an announced opening with no end ("From 18 Dec", "end date not announced"; computed as open for a year). Validate adds an info line for a missing `to`, so a forgotten one is visible. `link` (single) stays https only. The link checker already skips non-http URLs.
- **Validate hints (info only):** a word over 12 letters in `name`; `name_local` over 16 local-script characters; `name_romanized` over 36; `method: website` whose first link is a known booking platform. A first cut at 12 / 25 produced 95 info lines over current pages, too noisy once long names stack (below).
- **Hero names.** Fraunces and Inter now ship their latin-ext subsets with `unicode-range`, so ā ē ī ō ū render in the italic serif (checked on fuunji-tsukemen-shinjuku, "Fūunji"). Names are NFC-normalised. When `name_local` + `name_romanized` exceed 28 characters, each goes on its own line instead of wrapping mid-phrase. A title word of 10+ letters sets `--lw` and the phone title shrinks to fit it; `overflow-wrap` is `break-word`, not `anywhere`, so "Gyeongbokgung" no longer breaks mid-word.
- **Smaller fixes.** The When quick fact drops the date sub-line when `when.label` already contains the dates. The hero category chip keeps white text in dark mode (the dark-theme rule for pastel chips was overriding it). The phone footer has 16 px side padding. `atr shot areas` slices are labelled per country ("country_map korea", "areas korea"), and `--section "country_map korea"` shoots one country's map. `./atr blocks hero` documents that `focus` y has no effect on a phone for wide photos. The faq `asked` field says it is a date. `./atr new place` warns when the cached fx rate differs from the rate other cards in the city use, and takes `--fx-rate` / `--fx-date`. `./atr feedback --mark-seen --place <id>` keeps a per-page cursor in `places/_feedback-seen.json` (`places: {id: ts}`); a later global mark past it drops the entry.
- **Already there:** the stay scaffold already had `weather` and `book_ahead` uncommented (round 3.11).
- **Incident:** a script error of mine left `platform/lib/validate.js` empty for about five minutes (around 20:15–20:20 local). Any `./atr validate` or `./atr run` started in that window failed to import. The file was rebuilt from the full copy read at the start of the round plus this round's edits, and the error count over real data is 0, as before.
- **Open (not this round):** game note box / Must-Maybe-Skip replacement (the note box exists, see STATUS "notes on cards"), `social_score`, an `onward` cost field, per-holiday exclusion lists, a `persona` taste tag (orchestrator config), `when.content_tbd`.

## Coder notes, round 11A (network tools, 2026-11-12)
- **Probable root cause of the Commons 429s.** Since early 2026 Wikimedia serves thumbnails freely only at standard widths (20, 40, 60, 120, 250, 330, 500, 960, 1280, 1920, 3840 px) and rate-limits other widths hard. `media` asked for 2560 px (fetch) and 640 px (search previews), and downloaded the multi-MB original for anything up to 2560 px. Now fetch takes the 1920 px thumbnail of anything wider (the original when it is smaller), and search previews use 500 px. New photos therefore top out at 1920 px (640/1280/1920 WebP, no 2048); the largest slot needs 1280 and the hero warning is at 1600, so nothing fails.
- **One shared Commons queue for every session on the machine.** A lock under `.cache/locks/` lets one Commons request through at a time, with a minimum gap (1.2 s API, 3 s downloads). `.cache/commons-cooldown.json` holds one shared "not before" time: a 429 pushes it out by `Retry-After` when sent (the 600 s case), otherwise 30 s doubling per consecutive 429 up to 15 min, and a success resets it. Every session waits for it; nobody retries into a block. Each wait is printed on stderr ("rate-limited (HTTP 429, retry-after 600 s at 20:41) …; next try in 10 min"), never on stdout. The retry budget is now a time limit, not a count, so "attempt 6 of 5" can no longer happen.
- **Patient mode and the "fetch later" queue: both.** A normal call waits up to 2 min, which fits under the shell tool's 2-minute limit. A file that still cannot be fetched goes into `.cache/commons-queue.json`, with the place/area folder and `--as` name. The next `media fetch` for the same place fetches queued files first, or `media fetch <id> --queued` does it on its own. `--patient` waits up to 45 min and is meant for background runs. Both exist because neither covers every case. A queue alone loses the photo if nobody drains it, and patience alone blocks a foreground session. A queued file is never fetched into another curator's folder by someone else's call: only a call for the same target, or an explicit `--queued` with no target, drains it. Files that can never succeed (missing, non-free) leave the queue with a message.
- **Commons author** is trimmed to the name at fetch time: no HTML, "(talk | contribs)", licence sentences or Thai/English notes, at most 120 characters. The full text stays on the file page (`source_url`). The CLI says when it trimmed one. credits.yaml gets no new field.
- **Non-Latin names.** File names and preview folders with no Latin word (Hangul, CJK, Thai) get `photo-<digits>-<hash>` / `q-<digits>-<hash>`, so `남이섬 (4).JPG` no longer lands in `previews/4/` or collides with another `(4)`. `--as` is still the way to get a readable name.
- **media preview** takes several `File:` arguments and makes a contact sheet for any preview (a single file included); the sheet path is always printed. `media queue` lists queued files.
- **links false positives.** Node's `fetch` ignores `HTTPS_PROXY`, unlike curl. In a sandboxed session direct connections and DNS are blocked and only the proxy gets out, which matches "domain does not exist (DNS)" and "connection refused" while curl from the same shell worked. The same holds for Chrome (`ERR_CONNECTION_REFUSED` inside the sandbox, fine outside). The network commands (`media`, `links`, `render`, `geo`, `pdf`) now call `http.setGlobalProxyFromEnv()` when a proxy variable is set, and Chrome is launched with the same proxy; without one nothing changes. I could not reproduce a sandbox here (no proxy variables in this shell), so this part is reasoned, not observed. In addition, before a link is called dead or blocked:
  - a DNS or connection failure is retried once;
  - a DNS failure is checked with `dns.lookup` (the system resolver curl uses). If the host resolves, the link is a `timeout` warning that says so. If even en.wikipedia.org does not resolve, it is "DNS unavailable on this machine", not judged and not cached. When every host in a run fails DNS, all of them are reported that way;
  - the page is opened in Chrome. If Chrome shows it, the link is `ok` (the summary lists the links that only a browser opens). If Chrome sees a bot wall, it is `blocked`. Known bot-walled hosts and 404/410 are not opened in Chrome. `--no-browser` turns this off, and so does an injected `fetch` (tests).
  Every problem carries a `reason` (dns, tcp, tls, timeout, http, bot, walled, dns-flaky, dns-unavailable) and says it in the message. Network failures are cached for 1 h instead of 24 h. Cached problems say "[cached result from … UTC; --fresh re-checks]", and the summary counts cached results. The status names and counts are unchanged, so the runner's gate reads them as before (it runs with `fresh: true` and now gets the browser fallback too).
- **Verified for real:** `./atr links bang-krachao-bike-day --fresh` gave 6 ok, but DNS worked on this machine at that moment, so it does not reproduce the reported failure. A scratch page with narafestival.com and elysian.co.kr (TLS), panda.org.cn (timeout), madmonkeyhostels.com (403), trvlogue.com (429) and en.wikipedia.org gave 6 ok, the first 5 via Chrome. A made-up domain stayed dead ("does not exist (DNS); a browser could not open it either (net::ERR_NAME_NOT_RESOLVED)").
- **render**:
  - a hard `--timeout` (default 60 s) covers the whole render, including the steps that had no timeout before (`page.evaluate`, title, screenshot). When it runs out, render prints the text rendered so far plus "page never settled", or "the site never answered" when nothing loaded. A watchdog ends the process 20 s after the timeout whatever Chrome does;
  - "Execution context was destroyed" is survived by waiting for the new document and reading again (up to 4 times);
  - connection errors on load are retried once after 3 s, and the final message names the likely causes (rate limiting, sandbox proxy);
  - at most 3 renders run at once on the machine (lock slots); the others wait and say so. Five parallel renders here all succeeded, so I could not reproduce the parallel `ERR_CONNECTION_REFUSED` outside a sandbox; the proxy fix is the likely cure;
  - `--links` lists hrefs and `javascript:`/onclick targets; `--expand` opens `<details>` and `aria-expanded="false"` controls; `--click "<selector>"` (repeatable, Playwright selectors such as `text=1월`) runs before reading;
  - bot walls (Cloudflare "Just a moment", captcha, Access Denied, whaleguard, 403/429/432 with almost no text) get a "blocked by a bot check" line, and only 300 characters of the challenge are printed;
  - a final URL different from the one asked for is reported ("redirected: asked for … ended at …");
  - `--max-chars` was honoured all along. The cut seen at 24–30k characters is the shell tool, which truncates output near 30k. Text over 20k characters, or cut by `--max-chars`, is now also saved whole to `.cache/render/<host>-<hash>.txt`, announced at the top of the output.
  - Verified for real: the Changdeokgung ticket site (reported as hanging 10 min) rendered in 19 s. koreafirsthand.com and seoulskate.kr (curl times out on both from here) ended at the 45 s limit with no hang. timeanddate.com prints the bot-check line. Wikivoyage Ayutthaya with `--max-chars 300` saved all 58,610 characters.
- **`./atr pdf <url|file> [--pages] [--images]`** uses `pdfjs-dist@6.4.299` (Mozilla pdf.js) and `@napi-rs/canvas@1.0.13`, pinned exactly. Both are npm packages with prebuilt binaries, so no poppler or other system install is needed. I picked versions published at least two weeks ago. Text per page goes to stdout and the whole text to `.cache/pdf/<name>.txt`. `--images` renders page PNGs about 2000 px wide (at most 20 per call). Pages with no text layer are listed with the command to image them, and CJK cmaps are wired in. Downloads are capped at 100 MB. Verified on the 31 MB Seoul hiking guide from the friction log: text in about 1 s, and the page-3 map PNG renders legibly.
- **geo**:
  - a Wikidata 429 is now a note, not an error. OSM results still show, and a shared cooldown (`.cache/wikidata-cooldown.json`, Retry-After or 1 min doubling) skips Wikidata instead of hitting it on every call;
  - Japanese street addresses (kanji/kana with a prefecture or `--country japan` and block numbers) also go to GSI's address search. Verified for real: `東京都渋谷区代々木2-14-3`, which returned 0 results before, now gives a GSI block-level pin.

## Coder notes, round 12 (2026-11-12)
- **`./atr hostel-prices <id|url> --from --to`** reads the availability feed Hostelworld's own pages call (`prod.apigee.hostelworld.com/legacy-hwapi-service/2.2/properties/<id>/availability/?guests=1&num-nights=1&date-start=…`), one request per night, 250 ms apart, at most 31 nights. Per night it prints the cheapest dorm bed (per bed) and cheapest private (per room, with "sleeps N"), in the hostel's currency (or `--currency`) and R$ through `fx.js`, the rate plan, the cheapest refundable price when the cheapest one is non-refundable, the free-cancellation deadline, and the dated `/pwa/hosteldetails.php/<Name>/<City>/<id>?from=…&to=…&guests=1&currency=…` page. Name and city come from the property endpoint. Any Hostelworld URL form (pwa, `/hostels/p/<id>/`, the feed itself) or a bare id works. `--json` has everything.
  - **Sold out vs not on sale yet.** The feed answers both with empty `rooms`, so the command probes 7, 30 and 90 days after the last empty night (and two weeks from today when nothing in the range had beds). If a later date has beds, the empty night is SOLD OUT. If only earlier dates do, it is NOT ON SALE YET, and the note says the evidence and that "full on every later date checked" cannot be ruled out. With no beds anywhere it says NO BEDS ON SALE. This is a heuristic: Hostelworld gives no flag for it.
  - **Why `links` called the feed blocked.** Node's `fetch` (undici) gets HTTP 403 from that gateway on about every other request, and on the first request with the link checker's browser `Accept` header. `node:https` and curl get 200 every time, whatever the headers (8 of 8 with node:https; fetch alternated 403/200). `net.js` gained `httpsGet` (one connection per request, redirects followed), used by `hostel-prices`. The link checker now asks once more through it before it calls a 401/403 blocked. The pwa page URL was already ok. The reviews feed is also ok now, so the "blocked" info line on stay pages goes away after a `--fresh` check.
  - **Fallback.** The feed was readable every time from here, so the render fallback is a printed command, not automatic: a night whose feed request fails twice shows the error and `./atr render "<dated page>" --wait 5`.
  - **Verified for real:** `./atr hostel-prices 85799 --from 2027-01-14 --to 2027-01-17` (G Guest House Itaewon): 3 nights, 15 Jan dorm ₩42,349 non-refundable / ₩43,659 deposit only, private ₩143,181 / ₩147,609. `./atr render` of the printed 15 Jan page showed exactly those four prices. Jin's Paradise (295727) for 14–15 Jan: NOT ON SALE YET (beds on 5 Jan, none on 14 Jan or later; matches the friction log). Original Backpackers (330544) 1–2 Dec: ₩57,000 on 1 Dec, 2 Dec NOT ON SALE YET. Id 999999999: "no active property with this id". `checkUrl` on the printed page URL and two feed URLs, 3 times each: all ok. `./atr links g-guesthouse-itaewon original-backpackers-dongdaemun --fresh --no-browser`: 13 ok, 0 blocked (the friction log reported the feed and reviews URLs on these pages as blocked).
- **`./atr sun <area|place|city|lat,lng> [date] [--to date]`** is computed locally with the NOAA solar equations (Meeus), no network. Coordinates come from the area file, a place's `location`, the average of a city's places, or `./atr geo` as a last resort (and it says so). The time zone comes from the country, or from the coordinates for bare lat,lng; outside the five countries it is UTC with a warning, or `--tz`. It prints first light (civil dawn), sunrise, solar noon, sunset, dusk (civil), dark (nautical) and day length. Against the sunrise-sunset.org API (fetched once while building, not in tests): Bangkok 15 Dec, Seoul 15 Jan, Harbin 21 Dec and Tokyo 1 Dec all agree to within the rounding minute (e.g. Bangkok sunset 17:53 vs 17:52:41, Seoul dusk 18:05 vs 18:05:15). Those reference values are in the tests.

## Coder notes, route map (2026-11-12)
- **Base map: cached OSM tiles + SVG overlay, as asked.** `game/lib/routemap.js` puts everything in Web-Mercator world pixels at zoom 12. The server picks a square frame for the whole trip and one per country (`imageFrame`: the highest tile zoom that keeps the image ≤ 2048 px, square so it still covers a wide desktop map and a tall phone map), and `staticMap()` stitches it from the tile cache (`/route-map/<overview|country>.webp`). The browser places those images in an SVG with a world-pixel viewBox; zooming to a country is a viewBox animation, and the country's sharper image fades in over the overview. The route is drawn in a second SVG in screen pixels, so pins, lines and labels keep their size at any zoom. Considered Leaflet/MapLibre: smoother pan and pinch, but a third-party script, live tile requests from the browser and its own visual language, for a map that only needs five fixed views. Not worth it here.
- **Dark mode:** the tiles get the same invert/hue-rotate filter as the area overview maps; route lines have a dark casing under the light accent line, labels are pills on the surface colour. Checked in the dark screenshots.
- **Labels:** greedy placement (`layoutLabels`): eight spots around the pin, then two farther rings with a leader line; stops are placed first and always shown, then Must-not-placed, leg badges, Maybe, flight dates; anything else that doesn't fit is hidden. Pins closer than their size (Kyoto and Osaka on the whole-trip map) are nudged apart first (`relaxPins`). If a leg's stop labels still collide, that cluster gets one label in travel order ("Tokyo · Kyoto · Osaka"), which zooms to the country, where each city has its own label again. Text widths are measured with canvas text metrics and measured again once the web fonts load. On a phone the whole-trip map drops the leg badges and the "not placed" suffix (the chip row and the dashed rings carry them).
- **No invented order.** Only stops in the route are joined. Must cities not placed are rings with no line; the long-haul arrows only touch the first stop of the first leg and the last stop of the last leg. A stop's dates are worked out only while every stop before it has nights. The flight in/out wording comes from the config (`traveler.home`, the first leg's `from`, the last leg's `to`, "not booked" in its notes).
- **Persistence:** like notes, the whole list per country, latest line wins, unchanged saves skipped, saves 600 ms after the last edit and on leaving the tab (`keepalive`). The server checks every area id against that country's area files and config stops, and copies name and coordinates into the line for a stop with no area file, so the log reads on its own.
- **Config validation never throws.** `loadTripConfig` normalises `countries[].route` (shorthand `- shanghai` allowed, duplicates and bad stops dropped) and puts the problems on a non-enumerable `cfg.warnings`; the game shows them under the map and `./atr feedback` prints them. A typo in the route must not stop `./atr gaps` or a curator run.
- **The running game kept working during the build.** The client loads `/lib/routemap.js` lazily when the Route tab opens, so a server started before this change (which doesn't serve that file) still runs every other tab.
- **Phone tab bar:** 8 tabs don't fit (labels cut at 390 px). Hid My calls from the phone bar (it has its own link on Home, and Home is lit while it is open). The Route tab stays, since it is what the traveler asked for.
- **Touch targets:** 44 px on coarse pointers for the stepper, move/remove buttons, add chips, the "Whole trip" button and the Show skipped toggle; every pin has an invisible 22 px-radius hit circle, and labels are tappable too.
- **Not done:** drag to reorder, pinch/pan, adding a city with no area file from the game.

## Photos from the web (2026-11-25)
- **Why.** With Commons as the only source, 39 of 289 cards had no photo and 99 more opened with a stand-in (the street, the station, the building next door), because Commons has almost nothing for small restaurants, hostels and bars. The traveler decided: the site is personal, so copyright is not a constraint; a card must show the real place.
- **Rule.** Every card opens with a photo of the place itself. Sources in order: the venue's own pages, web image search, Commons. Stand-in and typographic heroes are last resorts and `./atr validate` warns about both. The rule lives in "Photos" in the curator guide; the reviewer treats a missing or stand-in hero as a `should`.
- **Tools.** `media web` (Bing Images, loaded in Chrome with its own User-Agent: plain HTTP requests and an overridden User-Agent get an empty or decoy page), `media scout <page>` (the images a page shows, at their largest `srcset` size) and `media grab <place> <image-url> --from <page-url>`. Credits get `license: All rights reserved (personal use)`, `origin: web`, the page as `source_url` and the host or `--credit` as author. Code in `platform/lib/media/web.js`.
- **Sizes.** `grab` refuses under 1000 px. A hero between 1200 and 1599 px is now an `info`, not a warning: a real photo of a small venue beats a sharp photo of something else.
- **If the site ever goes public,** the `origin: web` photos have to go first: `grep -l "origin: web" places/*/*/*/media/credits.yaml`.
